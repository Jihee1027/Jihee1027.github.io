RetroCore Gaming Console

  • DE10-Nano
  • RISC-V
  • SystemVerilog
  • ESP32
  • HDMI
  • PCB

A standalone console in development for an original two-player spaceship game. The four-person team's design combines C software on an FPGA-based RISC-V soft core, RTL tile-based graphics, and an ESP32 interface for two control stations, with a custom PCB planned. Role: hardware lead for the FPGA platform, display path, controller interface, power, and PCB planning.

Work

FPGA console hardware planning and bring-up: 640×480 video, two control stations with 4 analog inputs, 8 D-pad inputs, and 10 buttons, plus build and simulation checks.

Problem

The console needs dedicated controls and an original two-player game, with a graphics system that fits the FPGA's memory limits.

Action

Chose the DE10-Nano and ESP32-over-SPI input, planned six hardware stages, set up the tool and build flow, and designed the display test datapath.

Result

Board bring-up and the simulation flow are complete. Video output, controller input, and system integration are the next milestones.

System integration context

The work covers FPGA bring-up, controller communication, video output, and hardware/software integration.

Role and contribution

  • Hardware lead for a four-person team: FPGA platform, display path, controller interface, power and the custom PCB.
  • Checked ECE shop inventory and planned the initial prototype around available loan equipment.
  • Set up the FPGA tools and command-line build and simulation workflow, and completed initial board bring-up.
  • Designed the display test datapath (below) and wrote the hardware plan.
01

Why tile-based graphics

A full 640×480 frame with 24-bit color requires 921,600 bytes. With 8×8 tiles and one byte per index, the tile map takes 4,800 bytes, 192 times smaller than the full frame buffer, excluding tile graphics storage. The tile-based approach reduces memory use by storing tile positions rather than every pixel.

02

Why an ESP32 for input

The ESP32 reads the joysticks and buttons and passes the state to the FPGA over SPI, with the FPGA as master. SPI is simple enough to build directly into the FPGA and easy to check with a logic analyzer.

03

Supporting future games

The initial game is a two-player spaceship battle. The platform is designed to load games from storage so future games or controller mappings can use the same console.

02

Hardware plan

Divided hardware development into stages so blocks can be simulated and tested before integration. Stage 1 is complete. Platform planning moved from a board without built-in video output to the DE10-Nano with onboard HDMI.

03

Display test datapath

The first display milestone is a stable test image. The planned 640×480 color-bar path uses pixel counters, sync and data-enable generation, registered RGB outputs, and the DE10-Nano's onboard ADV7513 HDMI transmitter.

Timing requirements

RGB, horizontal sync, vertical sync, and data-enable must stay aligned with the pixel clock supplied to the transmitter. Counters wrap at the end of each line and frame, while comparators define the sync pulses and visible display region.

Verification plan

First simulate counter wraparound and sync and enable signals, then verify stable color bars on the board. ADV7513 configuration over I2C, pin assignments, and clocking also need to be checked against board documentation.

04

Bring-up and a repeatable build flow

Established a repeatable tool flow: installed FPGA tools, identified the board on the JTAG chain, and programmed an LED test design. Organized the project for module-level simulation, synthesis, and programming from the command line.

A lesson from the tools

Programming requires selecting the correct device on the JTAG chain, which includes both ARM and FPGA devices. Questa signal visibility was enabled to inspect the internal counter in simulation.

Next milestones

Next steps: verify video timing and stable HDMI output, test one ESP32 controller over SPI, and integrate both with the RISC-V game logic. Power, PCB, audio, and enclosure work follow once the interfaces are established.
