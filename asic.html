AHB Neural Network Accelerator

  • SystemVerilog
  • AHB
  • Design Compiler
  • QuestaSim

A small neural-network accelerator in SystemVerilog: a weight-stationary systolic array behind an AHB register interface, taken through simulation, synthesis and timing analysis. Three of us split the blocks. My part was the systolic array and the activation stage.

Problem

Neural-network inference is mostly multiply-accumulate work. We needed a small accelerator, reachable over a standard bus, that takes reduced-precision inputs and applies common activations.

Data

FP8 minifloat inputs and weights; test matrices (identity, bias, several activations, a 128-input vector); error cases such as NaN, infinity and AHB overrun; synthesis and timing reports.

Action

Built the 8×8 weight-stationary array with 64 processing elements and the activation stage, tested each block and then the top level, and helped debug the integration.

Result

The array and activation blocks were verified in simulation and ran inside the integrated design, which went through synthesis and timing analysis.

Process integration context

This project gave me the closest view of how a logical design becomes a timing-constrained physical implementation. Synthesis, interconnect delay, timing margin and physical-design constraints made the downstream effect of device and process behavior much more concrete to me.

01

My blocks

The 8×8 systolic array with 64 pipelined processing elements, their weight registers and the partial-sum pipelines, and the activation stage with ReLU, Leaky ReLU, binary and identity modes.

02

Teammates' blocks

The AHB subordinate, the controller with its input state machine, the SRAM data buffer and the top level were teammates' work. I helped debug the integration.

03

Where it got hard

Integration. Register controls, reset sequencing and data widths between the AHB interface, controller and array took more time than the array itself.

02

The systolic array datapath

Weights stay in place in each processing element while activations flow through staggered across eight lanes. Each element multiplies, adds the partial sum from above and passes the result on through pipeline registers. First one processing element, then the full array schematic.

03

The activation block

I also designed the activation stage, the last step before results leave the accelerator. It unpacks the 64-bit word into eight 8-bit minifloat values, applies the mode chosen by a 2-bit select, and packs the eight results back.

Four modes, one select

ReLU turns negative values into zero. Binary outputs +1 or −1 by sign. Identity passes the value through. Leaky ReLU keeps positive values and scales negative ones by 0.25. Each constant is an 8-bit minifloat encoding.

Zero is not negative

The sign check also tests whether the value is zero, so a negative-signed zero is not treated as a negative number. Small details like this are where numeric formats cause bugs.

04

How the design was checked

The group wrote a test plan that starts at the top level and drops into each block as needed. These are the tests for my array block, and the top-level checks around it.

Array block

  • Load weights: each weight lands in the right position based on the count.
  • Load inputs: inputs are staggered correctly across the lanes.
  • Multiply and sum: identity and normal cases in 8-bit minifloat, adding the previous sum down each column.
  • Output pipeline: the right alignment for the outputs of the last row and column.
  • Data out: the correct 64 bits from the pipelined outputs.
  • Reset clears data mid-operation, and the done pulse arrives with the data.

Top level and interface

  • A basic test with an identity matrix, zero bias and a pass-through activation.
  • A full test with bias, several activations and various input and weight matrices.
  • A 128-input vector test, and error cases such as an AHB overrun, NaN and infinity.
  • AHB register reads and writes, writes to read-only registers, too many weights or inputs, and writes while busy.
05

From RTL to a layout lab

RTL simulation ran in QuestaSim, synthesis in Synopsys Design Compiler, and timing analysis followed. In a separate layout lab on a provided USB design in Cadence Innovus I looked at I/O placement, interconnect delay and timing slack.
