AHB Neural Network Accelerator

  • SystemVerilog
  • AHB
  • Design Compiler
  • QuestaSim

A neural-network accelerator developed by a three-person team, using a weight-stationary systolic array and an AHB register interface. Contribution: systolic-array and activation-stage design, block verification, and integration debugging. The integrated design completed simulation, synthesis, and timing analysis.

Work

FP8 neural-network acceleration, with input and weight tests, a 128-input vector, numeric edge cases, AHB checks, and synthesis and timing review.

Problem

The accelerator needed a standard bus interface, reduced-precision multiply-accumulate operations, and support for common activation functions.

Action

Built the 8×8 weight-stationary array with 64 processing elements and the activation stage, tested each block and then the top level, and helped debug the integration.

Result

The array and activation blocks were verified in simulation and ran inside the integrated design, which went through synthesis and timing analysis.

Process integration context

Synthesis and timing analysis connected RTL decisions with implementation constraints, including interconnect delay and timing margin. This provides circuit-level context for how device and interconnect variation can affect performance.

01

Contribution

The 8×8 systolic array with 64 pipelined processing elements, their weight registers and the partial-sum pipelines, and the activation stage with ReLU, Leaky ReLU, binary and identity modes.

02

Team responsibilities

Teammates developed the AHB subordinate, controller and input state machine, SRAM data buffer, and top level. Integration debugging was shared across the team.

03

The main integration challenge

Coordinating register controls, reset sequencing, and data widths across the AHB interface, controller, and array required more debugging than the array alone.

02

The systolic array datapath

Weights remain in each processing element while activations enter eight lanes in a staggered sequence. Each element multiplies its inputs, adds the partial sum from above, and passes the result through pipeline registers. The diagrams below show a single processing element and the full array.

03

The activation block

Designed the activation stage to unpack a 64-bit word into eight 8-bit minifloat values, apply the mode selected by a 2-bit control, and repack the results before output.

Four selectable activation modes

ReLU turns negative values into zero. Binary outputs +1 or −1 by sign. Identity passes the value through. Leaky ReLU keeps positive values and scales negative ones by 0.25. Each constant is an 8-bit minifloat encoding.

Handling signed zero

The sign check also detects zero so negative zero is handled correctly. Verification covered this numeric-format edge case.

04

How the design was checked

The team test plan covered top-level behavior and individual blocks. The checks below cover the systolic array and its surrounding interfaces.

Array block

  • Load weights: each weight lands in the right position based on the count.
  • Load inputs: inputs are staggered correctly across the lanes.
  • Multiply and sum: identity and normal cases in 8-bit minifloat, adding the previous sum down each column.
  • Output pipeline: the right alignment for the outputs of the last row and column.
  • Data out: the correct 64 bits from the pipelined outputs.
  • Reset clears data mid-operation, and the done pulse arrives with the data.

Top level and interface

  • A basic test with an identity matrix, zero bias and a pass-through activation.
  • A full test with bias, several activations and various input and weight matrices.
  • A 128-input vector test, and error cases such as an AHB overrun, NaN and infinity.
  • AHB register reads and writes, writes to read-only registers, too many weights or inputs, and writes while busy.
05

Synthesis, timing analysis, and layout coursework

The accelerator was simulated in QuestaSim, synthesized in Synopsys Design Compiler, and checked through timing analysis. Separate Cadence Innovus coursework used a provided USB design to study I/O placement, interconnect delay, and timing slack.
