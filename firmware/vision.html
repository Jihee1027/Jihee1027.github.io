This public summary leaves out proprietary thresholds, recipe values, line and equipment identifiers and production counts.

01

Trigger-board resets and cells that skipped inspection

Vision Engineering, 2025–26. The trigger board tells the cameras when each cell passes. When it reset, cells already on the line could lose their inspection result.

Work

Keeping vision inspection running on electrode lines.

Problem

Trigger-board resets left cells already on the line without an inspection result.

Action

Traced the resets to low supply voltage, then updated the trigger-board firmware to mark every cell affected by a reset as NG.

Result

An affected cell can no longer pass without inspection, which reduced undetected defects.

02

Debugging at the signal level

When a vision failure kept coming back after a restart, I moved from the software symptom to the signals: equipment logs, oscilloscope traces and logic-analyzer captures of trigger timing, camera behavior, communication and cabling.

Software symptom

Missed or repeated inspections, gaps in image logging, and failures that returned after a reset.

Signal evidence

Compared waveforms and trigger timing with communication captures, equipment logs and production data.

Hardware cause

In one case the evidence led to the CIS hardware and its cables, and I found and corrected a cable-related fault.

03

Tuning inspection against production data

Each inspection view can flag good material (a false positive) or miss a real defect (a false negative), and a threshold trades one against the other. I tuned the parameters view by view and checked each change against production images before keeping it.

Result

False positives fell by about 10% after tuning, with stored images reviewed before each change was kept.

Raspberry Pi image logger

I also built a Raspberry Pi system at the unloader that captured region-of-interest images in sync with inspection and logged them centrally, so a defect trend could be checked against the actual images.

04

Reporting automation that runs unattended

Hourly production reports used to be collected by hand. I built a Python and Win32 tool on a Windows PC that fetches the latest summary, compares it with the last one and sends each section in order.

No duplicates

Each report is identified by its timestamp and checkpointed section by section, so a restart picks up at the missing part.

No bad data

If a report cannot be parsed, the tool logs it and sends nothing rather than an incomplete report.

Result

Inspection throughput rose about 7.2% (about 5,000 cells a day) after the tool was introduced.
