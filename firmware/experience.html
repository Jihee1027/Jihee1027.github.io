Pattern

What both internships had in common

The same habits I use on RetroCore, applied on a real production line.

Start from the symptom

A missed inspection, a reset, a rising defect rate. Write down exactly what fails and when before changing anything.

Go down to the signal or the data

Logs, oscilloscope and logic-analyzer captures for equipment; SPC and MES data for the line. The cause usually sits one layer below the symptom.

Verify against the spec

A change counts only when the same check passes afterward: the inspection images, the defect data, or the spec limit.

These public summaries leave out proprietary thresholds, recipe values, line and equipment identifiers and production counts.
